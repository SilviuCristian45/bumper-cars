# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Mașinuțe de Bâlci" — browser multiplayer top-down bumper-car arena, Romanian night-fair theme. npm workspaces monorepo: `shared/` (pure deterministic simulation), `client/` (Phaser 3 + Vite), `server/` (authoritative Colyseus 0.18). README and user-facing strings are in Romanian; code comments are in English. Requires Node ≥ 22.12. Architecture and UX patterns come from the sister project "Bombe și Petarde" (`E:\learn\petarde-bombe`): read it for reference, never modify it.

## Commands

Run from the repo root:

```bash
npm install
npm run dev          # client (http://localhost:5174) + server (:2568) together; dev:client / dev:server for one
npm test             # vitest for /shared, the client's DOM-free modules (client/test), then the server room tests
npm run typecheck    # tsc for shared + client + server
npm run build        # client/dist (static) + server/dist/index.js (single esbuild bundle)
npm run sim -- --bots usor,mediu,greu,greu --rounds 5 --seed abc -v   # headless bots-only match, prints rounds + standings (--powerups off)
npm run balance -w shared -- --matches 40 --lineup usor,usor,mediu,mediu,greu,greu   # bot tournament stats per level (--powerups off)
npm run og           # redraws client/public/og.png (link preview) + favicons from client/assets-src/icons.mjs (resvg)
```

Single test file / test name:

```bash
npm test -w shared -- test/rng.test.ts
npm test -w shared -- -t "<test name substring>"
npm run test:watch -w shared
```

Server room tests boot a real server on port 2569 (not 2568, which is the dev/prod port, and not Bombe's ports).

Normal visits go intro → name → menu → lobby → game → back to the lobby. Test URL options (all but `?touch` skip the menus and start a local match at once): `?debug` (hitboxes, heading/velocity vectors, hit credit, each bot's intent/target/input, tick/FPS, own speed/boost/slide/seq, power-up reach/time left, oil discs, next spawn timer), `?bots=1..5` (default 3), `?rounds=3|5|7`, `?seed=abc`, `?botlevel=usor|mediu|greu`, `?touch` / `?touch=0` (force the phone layout and touch controls, otherwise `(hover: none) and (pointer: coarse)`, see `client/src/device.ts`), `?tune` (driving-feel and power-up sliders, see below), `?powerups=0` (local match without power-ups). Online testing keeps the menus: `?online`, `?lag=ms&jitter=ms` (simulated network: `lag` = added round trip split over both directions, `jitter` = up to that much extra per message, order kept; `client/src/net/LagLine.ts`) and `?room=` all do, so `?online&debug&lag=120&jitter=30` plays online with the debug overlay (which then adds ping, the own car's prediction error being smoothed, unconfirmed inputs, big corrections per second). URL options are parsed in `client/src/urlOptions.ts`. In-game: `P` (or the touch "Pauză" button) pauses (local only), `Esc` (or "Ieși") opens the leave confirmation, `F` toggles fullscreen; after the match `Enter` (or a tap on the final panel) starts a new match in test mode, otherwise the host goes back to the lobby. `?room=CODE` (invite link) is joined from the menu after the name. **Resume after reload**: the online transport keeps `{ token, code }` (Colyseus reconnection token + room code) in sessionStorage (`client/src/net/resume.ts`, key `masinute.reconnect`; cleared by a consented leave, taken before every attempt so a failed one is not retried); on load `main.ts` → `startupRoute` skips the intro and the menu calls `resumeRoom()` (server keeps the seat 15 s); a `?room=` link to another room asks first ("Ieși din jocul curent...?": yes → `abandonResumableRoom()` reconnects and leaves for good, then joins; no → resumes). A resumed page's `Predictor` numbers inputs on from the server's `lastSeq` and the server forgets the player's input queue on reconnect (otherwise the new page's low seqs would be ignored as old).

## Architecture

### `/shared` — deterministic simulation (no Phaser, no DOM)
- Consumed as raw TypeScript (`exports` → `src/index.ts`); no build step.
- **Determinism is a hard rule**: no `Date.now()`, no `Math.random()`. Randomness goes through the seeded mulberry32 RNG whose state lives in the game state (`rng.ts`). Same seed + same inputs ⇒ byte-identical state.
- **Fixed-point**: every position, velocity, angle and timer in the state is an integer. `FP` sub-units per pixel; angles are integer steps with integer sin/cos tables (no `Math.sin`/`Math.cos`/`Math.sqrt` in the sim; use the integer helpers). Divisions are truncated explicitly. **Never use bitwise operators on fixed-point values** (`|0`, `>>`, `<<`, `~~` truncate to 32 bits); use `Math.trunc`/`Math.floor`. Bitwise is fine only for RNG/hash state that is a uint32 by design.
- Fixed tick: 30/s (`TICK_RATE`). The same `runTick`/`step()` runs in `LocalTransport`, in client-side prediction and on the server.
- State is flat (players as `Record<id, PlayerState>`, plain arrays) so it maps onto `@colyseus/schema`. A new state field must be added to `stateKeys.ts` (used by the mirror and the client's state rebuild) and to `server/src/schema.ts`.
- Input per tick: `{ seq, steer, throttle, boost }` (`steer`/`throttle` integers in -100..100, boost latched until the next tick).
- `tuning.ts`: the driving-feel numbers physics reads at run time (`TUNING`, defaults `DEFAULT_TUNING` from `constants.ts`). **Only the local `?tune` panel may change `TUNING`** (client and server must step with identical numbers); a test asserts the defaults. `applyGameTuning` runs at every game start (GameScene): back to `DEFAULT_TUNING`, then the saved values only for a local game with `?tune` (`test/tuning.test.ts`). To adopt tuned values, change the constants in `constants.ts` and re-run the balance test.
- Modules: `fixed.ts` (angle steps `ANGLE_STEPS` = 1024, literal quarter-wave sine table scaled by `TRIG_ONE`, `isin`/`icos`/`iatan2`/`isqrt`/`idiv` (never returns -0, so states survive JSON unchanged), `hash32`/`percent` for bot rolls); `constants.ts` (all tuning: speeds, grip, boost, mass, ring, timings, scoring); `physics.ts` (`driveCar`: steer/throttle/boost/friction/grip, lower grip for `slideTicks` after being hit; `collide`: disc–disc impulse with mass (boosting = heavier) and restitution, positional separation, knockout credit via `lastHitBy`/`lastHitTick`; `isOutside`); `sim.ts` (`applyInput`, `step`, countdown, ring shrink `ringRadiusAt`, eliminations and scoring, round end: one left = win +3, none left = draw, 90 s = timeout); `match.ts` (lobby/round/match lifecycle as in Bombe: `createGameState`, `addPlayer`, `addBot`, `startMatch`, `startRound` (seeded rotation of the spawn circle), `leavePlayer`, `backToLobby`, standings); `bot.ts`; `runner.ts` (`runTick` = inputs + bot decisions + `step`, `skipBotRound`); `protocol.ts` (wire contract, `INPUT_QUEUE_MAX`); `stateKeys.ts` + `netcode.ts` (see Netcode).
- Players are always iterated with `sortedPlayers` (slot order) and collision pairs in that order: never depend on object key order.
- **Power-ups** (`powerups.ts`, kinds `PU_*` in `constants.ts`): lobby option `GameState.powerups` (host, `setPowerups`, message `powerups`, default on). Two flat state slots `pu0*`/`pu1*` (kind/x/y/ticks; `powerupAt`/`livePowerups` read them) + `puTimer`; per player `effect`/`effectTicks` (Mici, Colac, Țuică, Arcuri: one at a time, a new one replaces it), `confusedTicks` (reversed steering), `oilX/oilY/oilTicks` (one puddle per car). In `step()`: `powerupsBeforeDrive` (timers, who stands on someone else's puddle → `driveCar(p, oiled)` + knockout credit to the owner), `collide` (Mici in `massOf`/speed, springs scale the impulse given to the victim, Țuică passes on via `powerHit`), `powerupsAfterCollide` (pickup by lowest slot, horn shove + credit, expiry/ring passing over, spawn from `state.rng` away from the edge/cars), `rescue` (Colac) before `eliminate`. **With power-ups off nothing there runs and the RNG is never drawn from**: `test/powerups.test.ts` pins a fingerprint of the pre-power-up simulation. Strengths/durations are `TUNING` keys (`hornRadius`…`springsPct`). Bots: `fetch` intent (`pickupChance`/`pickupRange`, safe spots only; `smart` (Greu) skips ones others reach first and steers right while confused), always hunt with Mici/Arcuri/Țuică, half the edge margin with Colac. The balance test runs with power-ups on and off.
- **Bots** (`BOT_PARAMS` per level: decision interval, aggression, edge margin + lookahead, boost range/alignment, escape boost, mistakes, aim noise). `botThink` is pure (rolls are hashes of `state.rng`, round, decision index, slot; it never advances the RNG), `botAct` returns an input only on decision ticks and the held input carries the bot in between. Retune against `test/balance.test.ts` and `npm run balance`.
- `test/sourceRules.test.ts` greps the source for banned APIs (`Date.now`, `Math.random`, float trig, `**`) and for bitwise operators outside `rng.ts`/`fixed.ts`/`roomCode.ts`. Tests build races with `makeRace` in `test/helpers.ts` (cars placed exactly, first fighting tick next).

### Netcode
- Server is authoritative: one `broadcastPatch()` after every simulation tick (`patchRate = null`, set **after** `setFixedTimestep`: in Colyseus 0.18 setting it before starts a timer that ticks the room clock on its own and starves the fixed-step loop). Every state carries its `tick` and each player's `lastSeq`; the tick's events go out right after its patch as `{ tick, events }`.
- The schema carries the whole `GameState` (rng included): the client rebuilds it exactly (`rebuildState`) and predicts with the same `runTick`. Field lists live once in `shared/src/stateKeys.ts` (`GAME_STATE_KEYS`/`PLAYER_STATE_KEYS`, used by the server mirror and the client rebuild; a test checks them against `createGameState`/`addPlayer`, a server test checks the rebuilt state equals the server's tick by tick). **A new state field goes into the key list and `server/src/schema.ts`.**
- `shared/src/netcode.ts`: `InputQueue` (server, per player, one input per tick, beyond `INPUT_QUEUE_MAX` = 4 the oldest is dropped and its boost carried to the next; repeated/old seqs ignored; a tick without input keeps the held steer/throttle), `parseInput` (validates the untrusted message), `Predictor` (client: `advance` numbers + applies + buffers an input, `reconcile` rewinds to the server state, drops `seq ≤ lastSeq`, replays the rest; only while the server is playing a round). `test/netcode.test.ts` runs a server and a predicting client over a simulated 100–150 ms network with jitter: a hit the client could not foresee is corrected and the prediction is exact again within a round trip and a few ticks.
- `client/src/net/ColyseusTransport.ts`: own car predicted (drawn between the last two predicted ticks; a correction is turned into an offset that fades with a 100 ms time constant, snapped beyond 4 car radii); everything else (other cars, ring, scores, phases: `getState()`) is the server timeline drawn `INTERP_TICKS` = 3 ticks (100 ms) behind the newest state, on a view clock that eases toward it; the own car's motion fields in `getState()` come from the prediction. Events play when the drawn state reaches their tick, those about the own car as soon as they arrive. Own ping/pong (`MSG_PONG`) every second. A hidden tab sends a neutral input at once (no frames, no inputs).
- Server validation: inputs only while `playing`, player id from the connection, more than 60 messages/s disconnects (`maxMessagesPerSecond`), lobby actions host-only (checked by the shared functions), 15 s reconnection, the host passes to the next human (never a bot) on leave.

### `/client` — rendering only
- Scenes read state and send messages only through `GameTransport` (`client/src/net/GameTransport.ts`): `setInput(DriveInput)` every frame (the transport samples it once per simulation tick, numbers it with `seq` and latches boost presses), `send(RoomMessage)` for lobby actions, `onEvents`, `view()` (where to draw every car and the ring this frame, `net/view.ts`), `netStats?()` (online, for `?debug`). `LocalTransport` runs `runTick` with a fixed-step accumulator at 30/s (max 250 ms catch-up) and blends the last two ticks (`TickBlend`). `ColyseusTransport`: see Netcode.
- Input (`client/src/input`): `InputSource.poll({ heading })` returns a `DriveInput` or null when unused; `CombinedInput` lets the first active source drive and any source boost. `KeyboardInput`: arrows/WASD (left/right steer, up gas, down brake/reverse), Space boost. `TouchInput` (HTML over the canvas, pointer events per finger): analog joystick (steers toward the joystick's direction relative to the car's heading, throttle proportional to the push, slow while turning around) and a boost button whose fill shows the cooldown; left-handed mode swaps them (`settings.ts`).
- Layout (`render/layout.ts`): 1 simulation pixel = 1 canvas pixel, arena centered at `ARENA_CX/CY`; desktop has the HUD panel on the right, touch has a `SIDE_W` thumb zone on each side (scores on the joystick side, round info on the boost side). Phones play sideways (`ui/orientation.ts`).
- Rendering: textures are drawn at startup with the 2D canvas API (`render/textures.ts`: diamond-plate floor, rubber rim, cars, glow/spark; `render/powerupTextures.ts`: the six power-up icons + oil puddle); `render/PowerupLayer.ts` (power-ups pop in, pulse, blink in their last 2 s; puddles), `render/powerupInfo.ts` (names, shouts, HUD hints, colors); CarView draws the effect aura (arc = time left) and the spinning "?" when confused; GameScene shouts "CLAXON DE TIR!" etc. over the car, horn `shockwave`; HUD shows the own effect + time left; `render/Arena.ts` (floor, chasing rim bulbs, darkened lost floor + red edge while the ring shrinks), `render/CarView.ts` (car, shadow, flickering antenna spark, name tag, local boost ring, fall-off animation), `render/Hud.ts`, `render/fx.ts` (particle bursts with a global cap; "Efecte reduse" = fewer particles, steady bulbs, no camera shake). `GameScene` draws the poses and ring of `transport.view()`; the joystick steers relative to the drawn heading.
- `debug/TunePanel.ts` (`?tune`, local games only): sliders applied live via `setTuning`, saved in localStorage (`masinute.tune`), "Copiază valorile" copies them as `constants.ts` lines; on wide screens the canvas makes room for it (`body.tuning`).
- `localStorage` goes through `client/src/storage.ts` (keys prefixed `masinute.`, failures ignored).
- Scenes (ported from Bombe și Petarde): `IntroScene` → `NameScene` (saved nickname, "Salut, X!") → `MenuScene` (Creează joc / Intră la un prieten with `ui/CodeInput.ts` 6 boxes / Joacă offline cu boți; `net/rooms.ts`: Colyseus endpoint `VITE_SERVER_URL`, default `/colyseus` (Vite proxy in dev, Caddy in production), empty = offline-only build; errors become Romanian messages, an unreachable/full server offers the offline game) → `LobbyScene` (code + Web Share/copy link when online, 6 rows, host tag, rounds, default bot level, ±Bot, per-bot level tag, Start) → `GameScene` (back to the lobby when the state returns to `lobby`). `LeaderboardScene` ("Clasament" from the menu, online builds only; `net/leaderboard.ts` fetches `GET /leaderboard`, a clear message when the server does not answer). The end-of-match panel shows "Ai intrat în top!" / "Record nou!" from `transport.newRecords()` (the `records` message; empty offline). Menu/lobby screens are HTML (`ui/dom.ts` `mountScreen`, canvas switches to ENVELOP behind them and back to FIT in the game) over `ui/backdrop.ts` (night fair: Ferris wheel, tents, chasing garlands; steady with "Efecte reduse"). Styles: `style.css` (page, touch controls, tune panel, rotate prompt) + `screens.css` (screens, dialogs, toasts, chrome).
- Audio (`client/src/audio/`, from Bombe): `sound.ts` (mute, saved as `masinute.muted`; optional files), `sfx.ts` (`playSfx(name, volume)`: Web Audio synths for the game (`bonk`, `boost`, `iesire`, `numaratoare`, `start`, `ring`, `runda`, `final`) and the power-ups (`claxon`, `ridicare`, `sughit`, `boing`, `colac`), each replaced by `public/audio/<name>.ogg|mp3` if present; table in README), `music.ts` (an original carousel-organ waltz on a lookahead scheduler, or a looped `muzica.ogg|mp3`; own gain ~0.12 into Phaser's master, so the mute button silences it; setting `music`, on by default, toggled in Setări / the desktop menu corner, `onSettingChange` stops it at once). ### `/server` — authoritative Colyseus 0.18 room
`@colyseus/core` + `ws-transport` + `schema` 5. Production: `node dist/index.js` (esbuild bundle, no `node_modules`), loopback `127.0.0.1:2568` (`HOST`/`PORT`/`MAX_ROOMS` env).
- `MasinuteRoom.ts`: room "masinute", the 6-character code is the roomId (`joinById`), max 6 (bots count), `MAX_ROOMS` (20) → `ERR_SERVER_FULL`, `lock()` at Start / `unlock()` back in the lobby, 15 s reconnection; `schema.ts` + `mirror.ts` (only changed values assigned); `registry.ts` (live rooms of the process); `app.ts`: `GET /health`, `GET /rooms/:code` (`open|full|playing|missing`, explains a refused join since Colyseus says "locked" for both full and running).
- `leaderboard.ts`: all-time leaderboard in SQLite via `node:sqlite` loaded with `process.getBuiltinModule` (no native deps, works in the esbuild bundle). `MIGRATIONS` list + `schema_version` (**append steps, never edit a released one**). `DB_PATH` env, default `data/leaderboard.db` in dev (`server/data/`, gitignored), `/var/lib/masinute/leaderboard.db` in production. Tables `matches` + `results` (points, wins = rounds won, knockouts, self_outs, place in the match); the top is a query: each lowercase nickname's best match (points, then wins, then oldest) + its match count, `LEADERBOARD_SIZE` = 15, cached 30 s (cleared by a save). `MasinuteRoom.saveMatch` on `matchEnd`: only humans still in the room, nothing with fewer than `LEADERBOARD_MIN_HUMANS` = 2 humans (offline games never reach the server); broadcasts `MSG_RECORDS` (`kind: 'top'` = entered the top 15, `'record'` = beat own best). DB errors are only logged; a DB that cannot be opened means no leaderboard, never a crash. `GET /leaderboard` → `{ available, entries }`. Tests: `server/test/leaderboard.test.ts` + the room tests (an in-memory board per test).
- Tests (`server/test/room.test.ts`) listen on 2569 themselves: `@colyseus/testing`'s `boot()` ignores the port for a `Server` instance and would take 2568. On Windows the 33 ms interval fires every ~47 ms, so the fixed-step loop sometimes runs two ticks per wakeup: tests must not assume one tick per `waitForNextTimestep()`.

## Game rules
- Round arena with an edge; a car whose center leaves the ring is out for the round. After 45 s of fighting (countdown excluded) the ring shrinks down to a minimum radius of ~2 car diameters. Round time limit 90 s: then nobody gets +3.
- "3, 2, 1, START!" countdown every round (cars frozen).
- Boost with ~3 s cooldown.
- Scoring: last car on the ring +3; knocking someone out +1 to whoever last hit them within 3 s; leaving the ring on your own −1. If the last cars are eliminated on the same tick nobody gets +3 (+1/−1 still apply). Match of 3/5/7 rounds.
- Bots Ușor/Mediu/Greu: one code path, parameters in `BOT_PARAMS` (reaction, aggression, mistakes); a deterministic balance test checks Greu > Mediu > Ușor (power-ups on and off).
- Power-ups (lobby, on by default): first ~10 s after START, then every 8–14 s, at most 2, gone after 10 s or when the ring passes; picked up by touch, active at once. Claxon de TIR (shove within ~3 cars, counts as a hit), Mici cu muștar (2× mass, slower, 6 s), Colac de salvare (cancels the next fall, 10 s), Ulei vărsat (puddle 8 s, sliding out from it = +1 to its owner), Țuică de prună (next car hit steers reversed 4 s; 8 s), Bară cu arcuri (2× shove, 5 s).

## TypeScript
Strict config in `tsconfig.base.json` with `noUnusedLocals`/`noUnusedParameters`, `verbatimModuleSyntax` (use `import type` for type-only imports) and `isolatedModules`.
